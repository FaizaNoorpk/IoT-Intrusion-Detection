# IoT Intrusion Detection Using the TON_IoT Dataset

## Overview

This project explores machine-learning and deep-learning approaches for network intrusion detection using the TON_IoT dataset.

The code includes data preprocessing, exploratory analysis, baseline classification, attack-type analysis, feature importance, and additional evaluation experiments.

**Research status:** Ongoing research. The work has not yet been peer-reviewed. Results should be treated as preliminary until the experiments and evaluation methodology have been fully validated.

## Research objectives

- Prepare network traffic data for machine-learning experiments.
- Compare conventional machine-learning and deep-learning approaches.
- Examine attack-category performance.
- Investigate feature importance and potential data leakage.
- Explore evaluation strategies intended to assess generalization.

## Dataset

The dataset is not included in this repository.

Obtain the TON_IoT dataset from its authorized source and review the applicable terms before use. Place the required network dataset file, 	Train_test_network.csv, in the project directory.

The preprocessing script is intended to generate 	Ton_iot_cleaned.csv. Subsequent scripts may require that cleaned file or the processed training and test files generated by prepare_data.py.

Do not upload raw datasets or derived files unless their sharing terms and research-disclosure implications have been checked.

## Environment

Python 3.11 is recommended as a starting point.

Create and activate a virtual environment:

`powershell
py -3.11 -m venv .venv
.\\.venv\\Scripts\\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
Run commands from the project directory.
1. Prepare the dataset using preprocessing.py.
2. Review the cleaned data and run prepare_data.py to generate processed training and test files.
3. Run the relevant baseline, deep-learning, and analysis scripts after confirming their input requirements.
4. Review generated metrics and outputs before reporting or comparing results.
Not every script is necessarily independent; some rely on outputs generated by earlier scripts. Inspect each script before running it.
Research integrity
Performance metrics depend on preprocessing, feature selection, data splitting, and evaluation design. High scores alone do not establish that a model generalizes to unseen devices, sources, or attack scenarios.

Claims should be supported by reproducible experiments, appropriate leakage checks, and clearly documented limitations.
Current limitations
- The public release is being prepared and has not yet been tested from a clean installation.
- Dataset files and generated outputs are excluded.
- Reproducibility and execution instructions require further validation.
- No performance claim is made by this README.
